# FR-007 Equipment List Management

## Purpose
Users open one list of all equipment and narrow it by category, status and assigned employee, and find equipment by number or serial number. Page 50100 "EQM Equipment List" (FR-001) already covers this through the standard BC search box, filter pane and the status views. FR-007 adds a teaching tip, an "Assigned Employee Name" column and two navigation actions into the filtered list. No code implements search or filtering.

## Behavior
- **Teaching tip:** one translated string pair on page 50100. `AboutText` uses `**Search**` bold markup. TODO(verify): the markup renders as bold in a sandbox.
- **Assigned Employee Name:** in `OnAfterGetRecord` the name is cleared first, then, if "Assigned Employee No." is not blank, one `Employee.Get` with `SetLoadFields` (first, middle, last name) and `FullName()`. A missing employee leaves the name blank and raises no error. Display only: the column cannot be filtered or searched. Filter on "Assigned Employee No." instead.
- **Page 50100 also serves as lookup page** for table 50100 and as the selection page of Return Equipment on the Employee Card. The new column and tip appear there too. TODO(verify) in sandbox that the Return Equipment lookup still works.
- **Equipment action (Categories):** the list opens with a fixed filter on the selected category; status views still work. A category without equipment opens an empty list.
- **Assigned Equipment action (Employee Card):** only Assigned equipment has an employee, so this shows current equipment. Past assignments are in Equipment Assignments (FR-006).
- **Search limit:** search covers visible columns only. If a user hides "No." or "Serial No." through personalization, search on that value stops working for that user (platform behavior).

## Permissions
EQM - Reader has `page "EQM Equipment List" = X`, `page "EQM Equipment Categories" = X`, `tabledata "EQM Equipment" = R`. Everyone with Equipment Reader can open, search and filter the list.

**Employee name:** the name column reads table Employee, which only D365 BASIC grants. Since NFR-002 the column is filled only when `Employee.ReadPermission()` is true; without it the name is blank and no error is raised. A user who sees the Employee Card but has no EQM set gets a permission error from Assigned Equipment (same as Equipment Assignments).
