# FR-039 Equipment Register Report

## Purpose
An inventory register of the equipment (GitHub issue #77). It lists each piece of equipment with its main data, so a user can see the whole inventory or a part of it on one printout or in one workbook. The user chooses the filters on the request page: **Category**, **Status**, **Employee** and **Purchase Date**. The report is read-only.

## What the report shows
One row per equipment, sorted by equipment number. Each row has these columns, in this order:

| Column | Content |
|---|---|
| Equipment No. | The equipment number |
| Description | The description |
| Category Code | The category code |
| Category Description | The description of the category, from the category list |
| Serial No. | The serial number |
| Manufacturer | The manufacturer |
| Model | The model |
| Status | The status |
| Assigned Employee No. | The employee the equipment is assigned to now |
| Assigned Employee Name | The full name of that employee, from the employee card |
| Location Code | The location code |
| Purchase Date | The purchase date |
| Purchase Cost | The purchase cost |
| Warranty End Date | The warranty end date |

Twelve columns use the standard field captions as headers. Category Description and Assigned Employee Name have no caption set in the report, so their header text is the column name (see "Known limitations").

## Request page filters
The request page has four filters, in this order: **Category Code**, **Status**, **Assigned Employee No.** and **Purchase Date**. They use the standard filter fields of Business Central, so a filter can be a single value, a list or a range, as usual in the platform.

## Rules
- **No default filter.** With no filter, every equipment is listed, including Lost and Disposed equipment.
- **Filters combine with AND.** Equipment is listed only when it matches every filter that is set.
- **Status** matches the current status. Final statuses (Lost, Disposed) are listed when the user filters on them.
- **Employee** matches the current **Assigned Employee No.** It does not look at the assignment history, so the register never shows past assignments.
- **Purchase Date** matches the purchase date. Equipment without a purchase date is listed only when no purchase date filter is set.
- **Category Description** and **Assigned Employee Name** are looked up once per code in one run.
- **Employee names are shown only to users who can read employees.** A user without read permission on Employee sees a blank name and no error. The same applies when the employee no longer exists: the name is blank and the report still runs.
- The report reads the current company only. It changes no data.

## Output
The output is one Excel workbook. The data sheet has the column headers in the first row, then one row per equipment. The platform also writes the filters the user chose into the workbook's hidden filter sheet (to be checked in sandbox check S2). The layout has no formatting, no totals and no pivot yet. A designed layout is a later decision (phase 2).

## Permissions
- **EQM - Reader** has execute on the report, so Equipment Reader can run it. Equipment Manager and Equipment Administrator inherit it.
- **EQM - API Consumer** has no access to the report.
- The report reads equipment, equipment categories and, when the user can read them, employees. A user without read permission on employees gets blank names, not an error.

## Design decisions
- One report with the platform request page filters, instead of a custom request page. The four filters the issue asks for are the standard filter fields.
- One compiler-generated Excel layout. A printable Word or RDLC layout is phase 2.
- The employee filter uses the current assignment, not the assignment history. A historical register ("equipment assigned to an employee on a date") is phase 3, if requested.
- The category description and the employee name are read in the report, not stored on the equipment table. No new FlowField and no new key on the table.
- No default filter, so the register is complete unless the user narrows it.
- Entry points: the Tell Me search, the Report group of the Equipment List and the Reporting area of the Equipment Manager Role Center.
- The report does not take the filters of the list page it is started from.

## Translations
New captions, ToolTips, the layout caption and summary, and the search terms are in `app/Translations/Equipment Management.g.xlf`, regenerated by the build. Never edit it by hand.

## Known limitations
- The Excel output is a plain data table. It has no formatting, totals or charts.
- The report has one layout. There is no printable layout.
- The register shows the current assignment only. There is no history view.
- Category Description and Assigned Employee Name have no caption set in the report, so their Excel headers show the column name, not a translated caption. Adding captions would be a layout change; decide when the layout is designed.
- The request page filters are not pre-filled from the list page the report is started from.
- Platform behaviour when no equipment matches the filters is not tested automatically. It is a sandbox check (S3).
