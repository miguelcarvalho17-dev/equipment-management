# FR-006 Assignment History Tracking

## Purpose
Every assignment of equipment is kept as a history entry (table 50103) with equipment, employee, start date, end date and
the user who assigned it. FR-004 and FR-005 already create and close the entries. FR-006 adds two hard rules so the history
cannot be lost: a Closed entry cannot be modified or renamed, and equipment that has any entry cannot be deleted.

Status: describes the code as implemented. **No automated tests (deferred, plan decision D4) and no sandbox run.** The app
version stays 29.0.0.0 (app.json unchanged). Namespace `MiguelCarvalho.EquipmentManagement`.

## History content
Field names and captions are unchanged. Mapping to the requirement:

| Requirement | Field (table 50103) |
|---|---|
| Equipment | "Equipment No." |
| Employee | "Employee No." |
| Start Date | "Assignment Date" (WorkDate at assignment) |
| End Date | "Closing Date" (WorkDate when closed) |
| Assigned By | "Assigned By" (UserId); also "Closed By", Status (Active/Closed) |

Entries are created and closed by FR-004/FR-005 logic (codeunit 50106 `UpdateAssignmentOnSave`): created when equipment
goes Available -> Assigned; closed when it leaves Assigned (Return, In Maintenance, Lost, Disposed). Reassignment is return
plus assign, so it produces two entries.

## Behavior
- **Closed entries are immutable.** `CheckEntryIsNotClosed` reads the stored entry (not `xRec`). If its Status is Closed it raises `ClosedEntryCannotBeChangedErr` (entry no., equipment no.). OnModify checks `Rec."Entry No."`; OnRename checks `xRec."Entry No."`.
  - Closing an Active entry passes, because the stored entry is still Active.
  - Active entries can still be modified and renamed (not locked).
  - Hard rule: no event, no IsHandled.
- **Equipment delete (table 50100 OnDelete):** first, Status = Assigned raises `DeleteAssignedErr` (unchanged). Then `AssignmentMgt.HasAssignmentHistory("No.")` is checked; if true, `DeleteHistoryExistsErr` tells the user to set the status to Disposed. Hard rule, no event.
  - `HasAssignmentHistory` counts Active and Closed entries (key Equipment No., Status; no status filter).
  - Only never-assigned equipment can be deleted. Equipment that was Assigned before FR-004 has no entry and can be deleted once it is no longer Assigned.
  - Nothing in the app deletes entries any more.
- **Renaming equipment or an employee** updates the numbers in history through the TableRelation cascade (D3); there is no rename block. TODO(verify): that the platform cascade does not run OnModify of table 50103 (which would now fail for closed entries). Check in the sandbox.
- **Not enforced when triggers are skipped:** `Modify(false)`, `ModifyAll(..., false)`, `Delete(false)`, `DeleteAll(false)`, RapidStart without validation. `Delete(false)` on equipment leaves orphan entries.
- A leftover Active entry on non-Assigned equipment (only after trigger-less writes) blocks deletion. Setting the equipment to Disposed does not close it. Repair: assign and return, then set to Disposed.

## Extending (events)
No new events, no signature changes, no standard events subscribed. `OnBeforeInsertAssignment` and `OnBeforeCloseAssignment` (codeunit 50106) are unchanged and run while the entry is not yet Closed in the database.

## Permissions
| Set | Table 50103 |
|---|---|
| EQM - Read | Read (unchanged). |
| EQM - Edit | `Rim` (was `Rimd`). Used through codeunit 50106; users cannot edit entries directly. Inherited by EQM - Admin. |
No EQM set can delete entries. Everyone with Equipment - Read can see the history.

## Upgrade and compatibility
- No schema change, no upgrade codeunit. Existing Closed entries become immutable and equipment that has entries becomes undeletable from the first publish.
- Removed `DeleteAssignments` was internal; no external caller.
- Supersedes FR-004 D6 and FR-005 D7 (delete rule).
- Translations: `app/Translations/Equipment Management.g.xlf` is regenerated by the build, not edited by hand.

## Privacy
Entries keep employee numbers and user names. Because entries are immutable and equipment with history cannot be deleted, there is no in-app way to remove or anonymise them. Ties to the open TODO on personal-data classification.
