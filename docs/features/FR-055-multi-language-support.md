# FR-055 Multi-Language Support

> **Sandbox verification (2026-11-24):** verified in a Business Central sandbox by the project owner; no defects were reported. The detailed results are not recorded here, so statements below that say "not verified" or carry `TODO(verify)` predate this run.

## Purpose
Shows the app's user interface in English (source), Portuguese (Portugal, pt-PT) and Spanish (Spain, es-ES). Captions, ToolTips, messages, error messages, labels and teaching tip texts follow the language a user chooses in Business Central (My Settings > Language).

Before this change, the app had only English texts. The generated `Equipment Management.g.xlf` existed, but no language file.

Status: implemented on branch `feature/FR-055-multi-language-support`, not committed, not merged. Plan: `docs/plans/FR-055-multi-language-support.md` (status approved). Target: AppSource.

## What changed
### Translation files (`app/Translations/`)
| File | Language | Units | Notes |
|---|---|---|---|
| `Equipment Management.g.xlf` | en-US (source) | 1040 | Generated by `al_build` from the current source |
| `Equipment Management.pt-PT.xlf` | Portuguese (Portugal) | 1040 | Every unit translated |
| `Equipment Management.es-ES.xlf` | Spanish (Spain) | 1040 | Every unit translated |

- Both language files have the same trans-unit IDs, in the same order, as the source file.
- Placeholders (`%1`, `%2`) are the same as in the source. Units with a maximum length stay within it.
- `app/app.json` already had `TranslationFile` in `features`. No `app.json` change was needed.

### Language fallback
- A user whose language is English, or any language without a file, sees English texts.
- Spanish (Mexico) is expected to use the Spanish (Spain) texts. This is a platform fallback that the plan expects, and it was not tested.
- Portuguese (Brazil) does not use the Portuguese (Portugal) texts. It shows English until its own file is added.
- The number and date format follows the Region setting, not the language (see FR-056).

### Translation tooling (`.github/scripts/`)
- `xlf_sync.py` (`sync`, `export`, `import`, `check`) keeps the language files in step with the source file. It uses only the Python standard library.
- `test_xlf_sync.py` tests the tool.
- Repo check 7, "Language files", runs `xlf_sync.py check` on every pull request. A missing, incomplete or wrong language file fails the check. A change to captions, ToolTips or labels therefore needs the translations in the same pull request.
- The warning in repo check 4 now says which steps to run.

### Test codeunit (`test/src/`)
- Codeunit 50153 "EQM Translation Tests", 8 tests (T1 to T8). They check that the Portuguese and Spanish texts reach the session: the table caption, the enum caption and the category error. A German session (no file) must show English. Each test restores the language before it asserts.

## Behaviour changes for users
- With Portuguese (Portugal) or Spanish (Spain) selected, the app shows its captions, ToolTips, messages and errors in that language.
- No field, page, action, permission, API or event changes.

## Not translated (decided)
- **Data.** Values that users enter are not translated. Default data written at install (equipment category descriptions, number series descriptions, job queue category description) uses the language of the session that installs the app. Existing rows keep their text.
- **Excel report column headers.** They come from the dataset column names, which XLIFF does not translate.
- **Picture file-dialog filter.** `PictureFilterTxt` is `Locked = true` and stays English. Phase 2.
- **Help articles.** `docs/help/*` stays English.
- **Other variants.** pt-BR and es-MX have no own file.
- **Telemetry, business events, API.** Unchanged. They stay in English and machine-readable.
