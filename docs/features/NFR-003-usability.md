# NFR-003 Usability

## Purpose
Every page of the app follows the standard Business Central pattern for its type, with grouped actions, imperative action ToolTips and Tell Me search entries. Two FactBoxes show assignment context: **Assignment Details** on the Equipment List and Card, **Assigned Equipment** on the Employee Card. The standard Notes and Links parts are added to the equipment pages. No new business functionality, no schema change.

Status: describes the code as implemented. Built with AL: Package with no warnings (reported by the user). Review verdict: APPROVE WITH CHANGES (fixes applied). **No automated tests (deferred, plan Q1; test codeunit 50163 reserved, not built). Sandbox checks UX-SB1 to UX-SB12 have not been run (see `docs/TODO.md`).** Risk R1 is unverified (see Known limitations). App version stays 29.0.0.0. Namespace `MiguelCarvalho.EquipmentManagement`.

## Conventions applied
- **Promotion:** promoted actions sit in named groups in `area(Promoted)`, never directly under it. `Category_Process` 'Process', `Category_Report` 'Report', `Category_Category4` = entity name ('Equipment') or 'Navigate'. Setup navigation is under Related > Setup and is not promoted. No legacy `Promoted`/`PromotedCategory` properties.
- **ToolTips:** field ToolTips start with "Specifies"; action ToolTips are imperative ("Open ...", "View ...", "Assign ...").
- **Tell Me:** Equipment Assignments is under History. Search terms: Equipment List 'devices, tools, hardware, company equipment'; Categories 'equipment types, equipment groups'; Setup 'equipment numbers, equipment number series'; Assignments 'equipment history, equipment loans, issued equipment'.

### Page 50111 "EQM Equipment FactBox" (on Equipment List and Card, `SubPageLink "No." = "No."`)
| Field | Shows |
|---|---|
| No., Status | Equipment number; status with the style from `GetStatusStyle()`. |
| Assigned Employee No. | Drill-down opens the Employee Card when the number is not blank, the user can read Employee and the employee exists; otherwise nothing happens, no message. |
| Employee Name, Job Title, Company Email | From the Employee record; blank when no employee is assigned, the employee is missing, or the user has no Employee read permission. No error is raised. |
| Assigned Since, Assigned By | "Assignment Date" and "Assigned By" of the active assignment, only when Status = Assigned. |
| No. of Assignments | `CountAssignments` (active and closed). Drill-down opens Equipment Assignments filtered on the equipment. |
| Last Assignment Closed | "Closing Date" of the newest closed entry (`GetLastClosedAssignment`, `FindLast` on key "Equipment No.", Status); blank when none. Read only when the count is above 0. |

The values are recalculated in `OnAfterGetRecord`; `OnFindRecord` clears them first. Four small reads per selected row (employee, active entry, count, last closed).

### Page 50112 "EQM Assigned Equipment FactBox" (on the Employee Card)
Repeater with No. (drill-down opens the Equipment Card), Description and Serial No. (hidden by default). The Employee Card part links with `SubPageLink "Assigned Employee No." = "No."`, and the page lists only equipment with Status = Assigned. The part is visible only when `EQM Equipment`.`ReadPermission()` is true (global `EQMShowEquipmentFactBox`, set in the extension's `OnOpenPage`).

### Notes and Links
`systempart(Notes)` is visible and `systempart(Links)` hidden by default on the Equipment List and Card. The platform stores them in the system table "Record Link". Notes can hold personal data that users type. In the base app a user who can read a record can add notes to it, so a Reader can add notes (plan Q7). TODO(verify): confirm in the sandbox (UX-SB11).

## Extending (events)
None published, none subscribed. Partners can extend both FactBox pages and every action group with page extensions. After the first release these become contracts: page IDs 50111/50112, their control names, and all action and group names.

## Permissions
- **EQM - Reader:** `X` on pages 50111 and 50112 (inherited by Manager and Administrator). No table data change; the FactBoxes read "EQM Equipment" and "EQM Equipment Assignment" (R for every role) and Employee (from D365 BASIC, guarded by `ReadPermission()`).
- Custom actions are not hidden per role (unchanged from NFR-002).

## Upgrade and compatibility
No schema change, no upgrade code, no Obsolete handling: nothing is released, so removing the promoted actionrefs `Categories_Promoted` and `Setup_Promoted`, the Role Center action `CategoryList`, and renaming the Setup action caption to 'Equipment Setup' need no deprecation. The action `Setup` and `Categories` names are unchanged. New procedures in codeunit 50106 are `internal`: no public API change.

## Code vs plan
- Page 50111 has an extra `OnFindRecord` trigger that clears the variables (not in the plan). Behavior matches the plan.
- Page 50111 reads the last closed assignment only when `NoOfAssignments > 0`; the plan read it whenever "No." was not blank. Result is the same.
