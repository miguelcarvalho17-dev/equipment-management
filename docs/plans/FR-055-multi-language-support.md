## Steps
1. **`Equipment Management.g.xlf`: refresh.** `al_addproject` (`app/`, then `test/`), run `al_build` on `app/`. `al_compile` does not write the `.g.xlf` (see anti-patterns.md, DECISIONS FR-056). If the MCP cannot load, run alc **in place** on `app/`. Keep any change.

2. **`.github/scripts/xlf_sync.py`: new, stdlib only.** Structure like `version_check.py`: `ROOT = Path(__file__).resolve().parents[2]` and `run(root) -> (errors, warnings, summary)`.
   - Constants: `LANGUAGES = ("pt-PT", "es-ES")`; `TRANSLATIONS = Path("app")/"Translations"`; `G_XLF`; language path `TRANSLATIONS/f"Equipment Management.{lang}.xlf"`; `NS = "urn:oasis:names:tc:xliff:document:1.2"`; `DONE_STATES = {"translated","final"}`; `PENDING_STATES = {"needs-translation","needs-review-translation"}`; `PLACEHOLDER_RE = re.compile(r"%\d+")`.
   - Parse: each `trans-unit` in order into a dict (`id`, `maxwidth`, other attributes in order, `source`, `target`, `state`, the two `note` elements).
   - Write: `write_language_file(path, lang, g_units, lang_units)` with string templates (not ElementTree serialization), byte-for-byte the `.g.xlf` layout: LF, UTF-8, line 1–2 verbatim, `<file datatype="xml" source-language="en-US" target-language="{lang}" original="{original}">`; each unit: same `<trans-unit>` line, `<source>`, `<target state="{state}">{text}</target>`, the two `<note>` lines; same indentation; escape `&`, `<`, `>` (and `"` in attributes); final newline.
   - `sync`: per language, load `.g.xlf` and existing file. Same source → keep target/state. Source changed → keep old target, state `needs-review-translation`. New unit → if a DONE unit with identical source exists, copy target as `translated` (translation memory); else empty target `needs-translation`. Removed unit → drop. Write in `.g.xlf` order. Print units/translated/pending/dropped.
   - `export <lang> <json-path> [--limit N]` (default 150): JSON array de-duplicated by source, `.g.xlf` order, pending only. Entry `{"source","notes": "<developer note> | <generator note>","current","target": ""}`.
   - `import <lang> <json-path>`: non-empty `target` entries; with `"id"` apply to that unit only, otherwise to every pending unit with equal source. Validate placeholder multiset and `maxwidth` first; failures reported (`IMPORT: <source>: <reason>`), not applied, exit 1. Applied units `translated`.
   - `check` / `run(root)`: TR1 `.g.xlf` missing/not well-formed (return early); TR2 language file missing; TR3 stray `*.xlf`; TR4 wrong `target-language` / `source-language` not `en-US` / `original` differs; TR5 ID missing in language file; TR6 orphan ID; TR7 stale source; TR8 state not DONE or empty target; TR9 placeholder multiset differs; TR10 `len(target) > maxwidth`. Summary `"{lang}: {n} units, {translated} translated, {same} identical to source"`; identical-to-source is not a warning; no warnings. `check` exits 1 on errors.

Tests: `test_real_repo_passes` (only after step 7); sync creates files with pending units; keeps existing translation; marks changed source for review; reuses translation memory; drops removed unit; export dedupes and respects limit; import applies to all units with source; import by id overrides single unit; import rejects placeholder mismatch; import rejects maxwidth; check complete file has no errors; negatives for TR2, TR3, TR4, TR5, TR6, TR7, TR8 (pending state), TR8 (empty target), TR9, TR10; written file is well-formed and escaped (`&`, `<` round-trip).

## Risks
- **Translation quality.** ~2 × 700 unique strings written by an agent; may be wrong in tone, inconsistent, or differ from Business Central's own terms. Reviewer spot-checks errors, ToolTips and enum captions against the glossary. Native-speaker review before a real AppSource submission.
- **Scale of steps 6–7.** ~10 batches per language. The developer must not stop with units pending; `check` must report 0. Reviewer checks 1040 targets per file, none empty (TR8).
- **Placeholders.** A dropped or duplicated `%1` breaks a message at run time. TR9 and import validation guard it.
- **`maxwidth`.** Default-data texts go into Code/Text fields at install; a long translation would be cut or fail. TR10 guards it.
- **Default data is language-dependent.** Category, number-series and job queue category descriptions are written in the installing session's language. Lookups use codes and codeunit IDs (checked in `EQMMonitoringJobMgt.Codeunit.al`, `EQMDefaultData.Codeunit.al`). No upgrade needed; existing rows keep English text.
- **CI container and non-English LCIDs.** If T1–T8 fail in CI because GlobalLanguage is rejected or translations are not applied, report it; fallback is to drop T1–T6 and keep the Python check as the only proof, with a decision entry.
- **Code that compares translated text.** None found (telemetry uses `Names()`, maintenance log uses `Format(…, 0, 9)`). Reviewer confirms no `.al` file in `app/` changed.
- **Stale `.g.xlf`.** If step 1 is skipped (alc on a scratchpad copy does not regenerate it), languages sync against old units. Reviewer confirms `al_build` ran in place.
- **Future PRs now fail on untranslated text (check 7).** Intended, but developer instructions do not mention it yet; consider updating `.claude/skills/al-review-checklist/SKILL.md` (line 43) and the al-patterns anti-pattern on the `.g.xlf`.
- **AppSource markets.** AS0057 expects translations for every locale the offer targets; other Partner Center markets need more files (later release decision).
