# FR-039 Equipment Register Report — Plan

> Request (verbatim): "FR-039 Equipment Register Report. The system shall provide an inventory register. Filters: Category, Status, Employee, Purchase Date" (GitHub issue #77)
> Status: **approved**

## Request
Add an equipment inventory register: a report that lists equipment with its main data. On the request page the user can filter by Category, Status, Employee and Purchase Date. Source: GitHub issue #77 (FR-039).
Target: AppSource

Tooling note: the AL MCP server returned "No projects are loaded" for both `al_getnextobjectid` and `al_symbolsearch` (the same as in FR-038). IDs were taken from a scan of every object declaration in `app/src` and `test/src`, plus the reservations in `docs/plans/*`:
- **Report 50100.** The app has no report yet, and report IDs are their own number space.
- **Test codeunit 50195.** Used today: 50161, 50162, 50178-50194. 50150-50177 are reserved by earlier plans. 50195-50199 are free.

The only base-application symbols used are already used in code that compiles in this repo: Employee `FullName()`, `ReadPermission()`, the fields "First Name", "Middle Name" and "Last Name", and codeunit "Temp Blob". The compile is the final check.

## Definition of done
- [ ] New report 50100 "EQM Equipment Register" (caption **Equipment Register**). Found in Tell Me (UsageCategory ReportsAndAnalysis, ApplicationArea All).
- [ ] The request page has one filter tab, **Equipment**, with these filter fields in this order: Category Code, Status, Assigned Employee No., Purchase Date. Several filters combine with AND. With no filter, all equipment is listed, including Lost and Disposed.
- [ ] One row per equipment, sorted by No. Dataset columns are exactly: EquipmentNo, Description, CategoryCode, CategoryDescription, SerialNo, Manufacturer, Model, Status, AssignedEmployeeNo, AssignedEmployeeName, LocationCode, PurchaseDate, PurchaseCost, WarrantyEndDate.
- [ ] CategoryDescription and AssignedEmployeeName are filled from the category and employee tables. Each code is looked up once per run (Dictionary cache).
  - The name is blank and there is no error when the user has no read permission on Employee, or when the employee no longer exists.
- [ ] The default and only layout is an Excel layout, `app/src/Reports/Layouts/EQMEquipmentRegister.xlsx`. The compiler generates it from the dataset and it is committed.
- [ ] Action **Equipment Register** on page 50100 "EQM Equipment List" (Reporting area, promoted in the existing Report group) and on Role Center 50110 (new Reporting area).
- [ ] Permission set 50100 "EQM - Reader" has `report "EQM Equipment Register" = X`. Manager and Administrator inherit it. API Consumer gets nothing.
- [ ] `app/Translations/Equipment Management.g.xlf` is regenerated by the build with the new captions, ToolTips, layout caption/summary and AdditionalSearchTerms.
- [ ] `app/` then `test/` compile with zero errors and zero warnings (CodeCop, UICop, AppSourceCop on app).
- [ ] New test codeunit 50195 "EQM Equipment Register Tests" and the change to 50162 compile. Report them as "Not verified: tests not executed (no CLI runner)".

## Out of scope
- A printable Word or RDLC layout, and a designed Excel layout (formatted table, totals, pivot). Phase 2.
- Historical register ("equipment assigned to employee X on date D" from assignment history). Phase 3 if requested.
- Any change to table 50100 (no new FlowFields, no new keys).
- Passing the list page's current filters into the report.
- `DataAccessIntent = ReadOnly`, `AllowScheduling` changes, request-page About texts.
- Any `app.json`, permission-set creation, event, upgrade or API change.

## Steps
1. **`app/src/Reports/EQMEquipmentRegister.Report.al`** (new file and folder). Structure:
   ```al
   namespace MiguelCarvalho.EquipmentManagement;

   using Microsoft.HumanResources.Employee;

   report 50100 "EQM Equipment Register"
   {
       Caption = 'Equipment Register';
       ApplicationArea = All;
       UsageCategory = ReportsAndAnalysis;
       AdditionalSearchTerms = 'equipment inventory, asset register, equipment report';
       DefaultRenderingLayout = EquipmentRegisterExcel;

       dataset
       {
           dataitem(Equipment; "EQM Equipment")
           {
               DataItemTableView = sorting("No.");
               RequestFilterFields = "Category Code", Status, "Assigned Employee No.", "Purchase Date";

               column(EquipmentNo; "No.") { IncludeCaption = true; }
               column(Description; Description) { IncludeCaption = true; }
               column(CategoryCode; "Category Code") { IncludeCaption = true; }
               column(CategoryDescription; CategoryDescription) { }
               column(SerialNo; "Serial No.") { IncludeCaption = true; }
               column(Manufacturer; Manufacturer) { IncludeCaption = true; }
               column(Model; Model) { IncludeCaption = true; }
               column(Status; Status) { IncludeCaption = true; }
               column(AssignedEmployeeNo; "Assigned Employee No.") { IncludeCaption = true; }
               column(AssignedEmployeeName; AssignedEmployeeName) { }
               column(LocationCode; "Location Code") { IncludeCaption = true; }
               column(PurchaseDate; "Purchase Date") { IncludeCaption = true; }
               column(PurchaseCost; "Purchase Cost") { IncludeCaption = true; }
               column(WarrantyEndDate; "Warranty End Date") { IncludeCaption = true; }

               trigger OnAfterGetRecord()
               begin
                   CategoryDescription := GetCategoryDescription(Equipment."Category Code");
                   AssignedEmployeeName := GetEmployeeName(Equipment."Assigned Employee No.");
               end;
           }
       }

       rendering
       {
           layout(EquipmentRegisterExcel)
           {
               Type = Excel;
               LayoutFile = './src/Reports/Layouts/EQMEquipmentRegister.xlsx';
               Caption = 'Equipment Register (Excel)';
               Summary = 'Lists the equipment that matches your filters, one row per equipment, in an Excel workbook that you can sort, filter and total.';
           }
       }

       var
           CategoryDescriptions: Dictionary of [Code[20], Text];
           EmployeeNames: Dictionary of [Code[20], Text];
           CategoryDescription: Text;
           AssignedEmployeeName: Text;
   ```
   Format the `column` blocks on several lines in the house style. Add two local procedures with `/// <summary>` doc comments:
   - `local procedure GetCategoryDescription(CategoryCode: Code[20]): Text`
     1. Exit '' when the code is blank.
     2. Return the cached value when `CategoryDescriptions.Get(CategoryCode, Value)`.
     3. Otherwise use a local `EquipmentCategory: Record "EQM Equipment Category"`: `SetLoadFields(Description)`, then `if Get(CategoryCode) then Value := Description`.
     4. `CategoryDescriptions.Add(CategoryCode, Value)` (a missing category caches ''). Exit Value.
   - `local procedure GetEmployeeName(EmployeeNo: Code[20]): Text`. Same cache pattern with `EmployeeNames`.
     - The lookup runs only when `Employee.ReadPermission()`. Then `Employee.SetLoadFields("First Name", "Middle Name", "Last Name")`, and `if Employee.Get(EmployeeNo) then Value := Employee.FullName()`.
     - No permission or no employee gives '', never an error. Cache the result either way.

   No Commit, no locking, no UI, no labels needed. Why: RequestFilterFields gives the four filters the issue asks for, using the platform's filter UI, with no custom request-page code. The cache avoids a Get per row. The platform already writes company, user, date and active filters into the Excel system sheets, so no header columns are needed.

## Tests
New codeunit 50195 "EQM Equipment Register Tests". "Listed" means that the equipment number appears in the report XML output.

**Content**
- [SCENARIO 1] The register lists equipment with category description and employee name.
  - [GIVEN] Categories C1 and C2, employees EMP1 and EMP2. E1 in C1 assigned to EMP1, E2 in C2 assigned to EMP2, E3 in C1 Available.
  - [WHEN] Run with filter Category Code = C1|C2.
  - [THEN] E1, E2 and E3 are listed. The output contains both category descriptions, plus `FullName()` of EMP1 and of EMP2.
- [SCENARIO 2] (failure path) An assigned employee that no longer exists does not stop the report.
  - [GIVEN] E1 in C1 with Status Assigned and "Assigned Employee No." set to a number with no Employee record.
  - [WHEN] Run with Category = C1.
  - [THEN] No error, and E1 is listed.

**Category filter**
- [SCENARIO 3] Matching category is listed. [GIVEN] E1 in C1, E2 in C2. [WHEN] Category = C1. [THEN] E1 is listed.
- [SCENARIO 4] (negative) Other categories are not listed. Same GIVEN and WHEN. [THEN] E2 is not listed.

**Status filter**
- [SCENARIO 5] Matching status is listed, final statuses included. [GIVEN] E1 Available and E2 Disposed, both in C1. [WHEN] Category = C1, Status = Disposed. [THEN] E2 is listed.
- [SCENARIO 6] (negative) Same GIVEN and WHEN. [THEN] E1 is not listed.

**Employee filter**
- [SCENARIO 7] Equipment of the filtered employee is listed. [GIVEN] In C1: E1 assigned to EMP1, E2 assigned to EMP2, E3 Available. [WHEN] Category = C1, Assigned Employee No. = EMP1. [THEN] E1 is listed.
- [SCENARIO 8] (negative) Same GIVEN and WHEN. [THEN] E2 and E3 are not listed.

**Purchase Date filter** (R = Today() - Random(365), N = Random(10))
- [SCENARIO 9] Both boundaries are included. [GIVEN] In C1: E1 with purchase date R, E2 with R + N. [WHEN] Category = C1, Purchase Date = R..R+N (`SetRange`). [THEN] E1 and E2 are listed.
- [SCENARIO 10] (negative) Dates outside the range and blank dates are excluded. [GIVEN] In C1: E3 with R - 1, E4 with R + N + 1, E5 with 0D. [WHEN] Same filter. [THEN] E3, E4 and E5 are not listed.

**Combination**
- [SCENARIO 11] (negative) All filters must match. [GIVEN] In C1: E1 assigned to EMP1 with purchase date R, and E2 assigned to EMP2 with purchase date R. [WHEN] Category = C1, Status = Assigned, Employee = EMP1, Purchase Date = R. [THEN] E1 is listed and E2 is not.

**Permissions (changed codeunit 50162)**
- [SCENARIO 8 extended] Reader has Execute on every report in 50100-50149, including 50100. Not vacuous because at least one report exists.
- [SCENARIO 4 extended] (negative) API Consumer has no entry for report 50100.

Existing tests likely affected: `test/src/EQMRolePermissionTests.Codeunit.al` (changed on purpose; it fails if step 3 is missed). None else.

## Assumptions
- **Employee** means the current "Assigned Employee No.", not assignment history.
- **No default filter**, so Lost and Disposed equipment are included unless the user filters on Status.
- The generated Excel layout (Data sheet with all columns) is an acceptable first delivery. Formatting it is a human design task in Excel.
- The four filters as plain RequestFilterFields are enough: date ranges and multiple values come from the platform.
- `Report.SaveAs` with an empty parameter string and a filtered RecordRef applies the RecordRef filters to the data item.
- Tests may not use "Library - Report Dataset" (needs a new test-app dependency = `app.json` change, stop list). Output is checked with text `Contains`.
- No mismatch found between `CLAUDE.md` and `app/app.json`.

## Risks
- **MCP unavailable.** `al_symbolsearch` and `al_getnextobjectid` failed ("No projects are loaded"). The compile in steps 2, 6 and 9 is the check. The reviewer should grep that `report 50100` and `codeunit 50195` are declared nowhere else.
- **Layout generation.** If the build tool does not generate the xlsx, the build fails with AL0709 (mitigation in step 2). The xlsx must be committed, or CI fails. The reviewer checks that it exists and that its Data sheet header has the 14 column names.
- **Dataset is a contract.** Never rename or remove a column once released; only add.
- **XML output shape.** Tests rely only on text appearing in output. If `Report.SaveAs` with '' parameters raises "invalid request page data" in the sandbox, change `RunRegister` to `Report.RunRequestPage` plus a `[RequestPageHandler]` (needs a different TransactionModel). Report it; do not work around it silently.
- **Empty result.** Platform behaviour when no equipment matches is not tested automatically; sandbox check S3.
- **Performance.** One pass over table 50100, plus one Get per distinct category and employee. No new key.
- **Permissions and privacy.** Employee names are shown only to users who can read Employee (`ReadPermission()` guard).
- **Multi-company and concurrency.** Read-only, current company only, no locks, no Commit.
- **Test ID range.** After 50195, only 50196-50199 are free in the test range. Flag for future features.
- No separate AppSource validation ran; the reviewer checks the AppSource rules.
