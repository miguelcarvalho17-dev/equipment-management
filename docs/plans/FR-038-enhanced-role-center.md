> Request (verbatim): "FR-038 Enhanced Role Center" (GitHub issue #76)
> Status: **approved**

## Request
Add four operational KPI tiles to the existing equipment Role Center/dashboard cue part (page 50106 "EQM Equipment Cues", used by RC 50110 and dashboard 50109): Equipment Requests Pending Approval, Warranties Expiring This Month, Open Maintenance Activities, Total Assets Value. Source: GitHub issue #76 (FR-038).

Target: AppSource

Tooling note: the AL MCP server returned "No projects are loaded" for `al_symbolsearch` and `al_getnextobjectid`. The test codeunit ID comes from a scan of `test/src` plus earlier plans: FR-009 reserved **50161 "EQM Dashboard Tests"** for this cue part and never built it. Used now: 50162 and 50178-50194. No base-application symbol is needed; every symbol is this app's own and was read in source.

No new app object is needed: new fields on the app's own temporary cue table, page controls, one line in the existing filter procedure, and one new test codeunit.

## Definition of done
- [ ] Page 50106 "EQM Equipment Cues" has a new cuegroup **Operational Indicators**, directly after the existing **Equipment** group, with four tiles in the issue's order:
  1. **Requests Pending Approval**: count of "EQM Equipment Request" with Status = Pending Approval. Drill-down opens "EQM Equipment Requests" filtered to that status.
  2. **Warranties Expiring This Month**: count of equipment whose "Warranty End Date" is from today up to and including the last day of the current month. Lost and Disposed excluded. Drill-down opens "EQM Equipment List" with the same filter.
  3. **Open Maintenance Activities**: count of "EQM Maintenance Record" with Status = Open. Drill-down opens "EQM Maintenance Records" filtered to Open.
  4. **Total Assets Value**: sum of "EQM Equipment"."Purchase Cost" over equipment that is not Lost or Disposed, as an amount in LCY. Drill-down opens "EQM Equipment List" with the same filter.
- [ ] Existing tiles, groups and order unchanged. RC 50110 and dashboard 50109 show the new tiles with no layout change, since both already host part 50106.
- [ ] The Refresh action on 50109 and RefreshOnActivate also refresh the new tiles (FlowFields of the same record, no code).
- [ ] `SetWarrantyCueFilters` also sets the new "Warranty Month Filter". `0D` means today.
- [ ] Every new field has a Caption and a ToolTip. No `ToBeClassified`.
- [ ] Dashboard 50109 AboutText describes the new tiles.
- [ ] `app/Translations/Equipment Management.g.xlf` regenerated by the build with the new captions, ToolTips and changed AboutText.
- [ ] `app/` then `test/` compile with zero errors and zero warnings (CodeCop, UICop, AppSourceCop on app).
- [ ] New test codeunit 50161 "EQM Dashboard Tests" compiles. Report as "Not verified: tests not executed (no CLI runner)".
- [ ] No permission set changes: no new app object, and Reader already has R on Equipment Request, Maintenance Record and Equipment. Test 50162 stays green.

## Tests
New codeunit 50161 "EQM Dashboard Tests".

**Requests Pending Approval**
- [SCENARIO 1] Pending requests are counted. GIVEN baseline B, N = Random(3) requests Pending Approval; THEN value = B + N.
- [SCENARIO 2] (negative) Other statuses not counted. GIVEN baseline B, one request each Open, Approved, Rejected, Completed; THEN value = B.

**Warranties Expiring This Month** (R = MidMonthDate(), EOM = CalcDate('<CM>', R))
- [SCENARIO 3] Warranties ending from R to EOM counted, both boundaries included. GIVEN baseline B, Available equipment with end dates R, R + Random(5), EOM; THEN B + 3.
- [SCENARIO 4] (negative) Outside the window not counted. GIVEN baseline B, end dates R - 1, EOM + 1, 0D; THEN B.
- [SCENARIO 5] (negative) Lost and Disposed not counted. GIVEN baseline B, one Lost and one Disposed with end date R + 1; THEN B.
- [SCENARIO 6] (boundary) On the last day of the month only that day counts. GIVEN R2 = EOM, baseline B with R2, end dates R2 and R2 + 1; THEN B + 1.
- [SCENARIO 7] 0D means today. WHEN `SetWarrantyCueFilters(EquipmentCue, 0D)`; THEN `GetRangeMin("Warranty Month Filter")` = Today() and `GetRangeMax` = CalcDate('<CM>', Today()).

**Open Maintenance Activities**
- [SCENARIO 8] Open records counted. GIVEN baseline B, equipment E with N = Random(3) open records; THEN B + N.
- [SCENARIO 9] (negative) Posted records not counted. GIVEN baseline B, E with Random(3) posted records; THEN B.

**Total Assets Value**
- [SCENARIO 10] Cost of equipment in use is summed. GIVEN baseline V, equipment Available, Assigned, In Maintenance each with cost Random(100000) / 100, sum S; THEN V + S.
- [SCENARIO 11] (negative) Lost and Disposed excluded. GIVEN baseline V, one Lost and one Disposed with costs > 0; THEN V.

**UI wiring**
- [SCENARIO 12] The cue page shows the four tiles with the calculated values. GIVEN DisableRoleCenterNotifications(), one pending request, one open maintenance record, one Available equipment with purchase cost and end date Today(); WHEN `TestPage "EQM Equipment Cues"` opened with OpenView; THEN the four page values equal those of a cue record initialised with Today().

Existing tests likely affected: none. No test references the cue table, page 50106 or codeunit 50107 (grep). `test/src/EQMRolePermissionTests.Codeunit.al` (50162) is unaffected: no app object added.

## Assumptions
- **Total Assets Value** = sum of "Purchase Cost" (the only value field on equipment), LCY. Lost and Disposed excluded (same rule as the warranty and planned-maintenance tiles). Statuses added by extensions are included. No depreciation (no fixed-asset dependency).
- **Warranties Expiring This Month** runs from today to the last day of the current month. Warranties that ended earlier in the month are already in the Expired tile and, by the existing warranty status rule, are Expired. Lost and Disposed excluded. Overlaps the "Warranties Expiring in 30 Days" tile by design (calendar vs rolling window); neither existing tile changes.
- **Open Maintenance Activities** = maintenance records with Status Open (enum has only Open and Posted). Counts records, not equipment (the existing "Equipment in Maintenance" tile counts equipment). Open records of equipment later Lost/Disposed still count; a count CalcFormula cannot filter on equipment status anyway.
- **Requests Pending Approval** = Status Pending Approval only; Open requests have not been sent for approval.
- Test codeunit 50161 is used because FR-009 reserved it as "EQM Dashboard Tests"; 50195 stays free.
- Tests insert data with `Insert(false)`/`Modify(false)` and assert deltas because the test app depends only on Library Assert (adding a test library is an `app.json` change, on the stop list). Same as 50194.
- No escalation needed: no `app.json`, permission-set or data change. The only object that grows is a temporary, Internal table.

## Risks
- **MCP unavailable.** `al_symbolsearch` and `al_getnextobjectid` returned "No projects are loaded". The compile in steps 5 and 7 is the check. The reviewer should confirm 50161 is not used in `test/src` (grep found no declaration).
- **FlowFields on a temporary cue record.** Relies on the platform calculating FlowFields for a temporary source record. Existing fields 10-53 already work this way (FR-009 R1); risk low.
- **Sum without SIFT.** "Total Assets Value" scans table 50100 on every Role Center open. Volumes are small. If needed, a later non-breaking key `(Status) SumIndexFields = "Purchase Cost"`. The warranty date filter has no key either, same as existing tiles.
- **Notifications in the UI test.** Page 50106 OnOpenPage calls `ShowRoleCenterNotifications`. Without `DisableRoleCenterNotifications()` the test depends on company data. If the TestPage still raises an unhandled notification, the reviewer checks that DisableNotification registered the defaults first.
- **AppSourceCop AS0139** ("New table fields must use AllowInCustomizations") only fires against a baseline; `app/AppSourceCop.json` has none and existing cue fields do not set it. If it appears, add `AllowInCustomizations = Never;` to the five new fields. Do not suppress.
- **Permissions.** Users without R on "EQM Equipment Request" or "EQM Maintenance Record" get a permission error when the cue calculates. Every EQM permission set (Reader and up) grants R on both.
- **AppSource contract.** Page 50106 controls and the new cuegroup become public layout after release. Table and codeunit are Internal. Everything is additive; no existing field, control or signature changes.
- **Multi-company and concurrency.** FlowFields are per company. The part is read-only: no locking, no Commit. Values are as current as the last refresh, like the existing tiles.
- No mismatch between `CLAUDE.md` and `app/app.json` found (BC 29, runtime 18.0, range 50100-50149). No separate AppSource validation ran; the reviewer checks the AppSource rules.
