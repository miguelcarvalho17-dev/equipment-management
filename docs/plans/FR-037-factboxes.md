# FR-037 FactBoxes — Plan

> Request (verbatim): "FR-037 FactBoxes — https://github.com/miguelcarvalho17-dev/equipment-management/issues/75"

## Request
Add three read-only FactBoxes to the Equipment Card (page 50101), from GitHub issue #75 (FR-037):
- **Equipment Summary**: Current Status, Assigned Employee, Warranty Status.
- **Equipment Statistics**: Assignment Count, Maintenance Count, Total Maintenance Cost.
- **Attachment Summary**: Document Count, Image Count.

Target: AppSource

Tooling note: the AL MCP server did not connect when this plan was made (`altool` not found), so `al_symbolsearch` and `al_getnextobjectid` were not available.
- **Object IDs** come from a scan of every object declaration in `app/src` and `test/src`, plus the ID reservations in earlier plans (FR-026 C10, FR-029, FR-034, FR-036).
- **Standard symbols** are marked "Not verified" below. Where existing compiled code or the FR-024 events report already uses a symbol, that is cited as supporting evidence.

## Definition of done
- [ ] The Equipment Card FactBox pane shows three new parts, in this order directly after **Picture**: **Equipment Summary**, **Equipment Statistics**, **Attachment Summary**. All existing parts stay on the card with unchanged control names: Picture, AttachedDocuments, EquipmentFactBox, MaintenanceFactBox, Links, Notes.
- [ ] **Equipment Summary** shows:
  - Status, styled like the card.
  - Assigned Employee No. Drilling down opens the Employee Card. Nothing happens when the field is blank or the user cannot read employees.
  - Assigned Employee Name.
  - Warranty Status: Active, Expiring Soon, Expired, or blank when there is no warranty end date. Styled like the card.
- [ ] **Equipment Statistics** shows:
  - Assignment Count: all assignment entries, active and closed. Drilling down opens Equipment Assignments filtered to the equipment.
  - Maintenance Count: posted maintenances only. Drilling down opens Maintenance History.
  - Total Maintenance Cost: posted only. Drilling down opens Maintenance History.
- [ ] **Attachment Summary** shows:
  - Document Count: Document Attachment rows of this equipment whose File Type is not Image.
  - Image Count: rows whose File Type is Image.
  - Drilling down on either number opens Document Attachment Details for the equipment. The counts refresh after it closes.
- [ ] Rows of another equipment, or of another table that has the same "No.", are never counted.
- [ ] On a new, unsaved card every new FactBox shows 0 or blank, and no error is raised.
- [ ] Every new field has a Caption and a ToolTip, or inherits both from the table field. ApplicationArea = All is set on each new page.
- [ ] The card AboutText describes the three new FactBoxes.
- [ ] Permission set "EQM - Reader" (50100) has X on the 3 new pages and the new codeunit. Manager and Administrator get them through inclusion. "EQM - API Consumer" is unchanged.
- [ ] `app/Translations/Equipment Management.g.xlf` is regenerated by the build and contains the new captions and ToolTips.
- [ ] `app/` and then `test/` compile with zero errors and zero warnings (CodeCop, UICop, AppSourceCop).
- [ ] The new test codeunit 50194 compiles. Report it as "Not verified: tests not executed (no CLI runner)". Existing test 50162 must still be logically satisfied (see Tests).

## Out of scope
- Equipment List, Maintenance pages and Employee Card FactBoxes. The request names the Equipment Card only.
- Removing, hiding or changing the existing parts "EQM Equipment FactBox" (Assignment Details) and "EQM Maintenance FactBox", or the standard "Doc. Attachment List Factbox". See DECISIONS.
- Date-filtered statistics, average cost, open-maintenance counts. The existing Maintenance FactBox already shows the open-maintenance counts.
- Counting the equipment Picture (MediaSet field 24) as an image.
- Page background tasks. The counts are cheap COUNT and SUM calls on indexed keys.
- Refactoring the card's existing `Attachments` action to use the new codeunit (no drive-by refactor).
- Any `app.json` change, event, table, field, upgrade code, or API page change.

## Steps
1. **`app/src/Attachments/EQMEquipmentAttachmentMgt.Codeunit.al`**: create codeunit 50137 "EQM Equipment Attachment Mgt."
   - Header: `Access = Internal;`, `using Microsoft.Foundation.Attachment;`, an XML doc summary "Counts and shows the files attached to equipment."
   - `internal procedure CountDocuments(EquipmentNo: Code[20]): Integer`:
     - Return 0 if EquipmentNo = '' or `not DocumentAttachment.ReadPermission()`.
     - Otherwise call `FilterEquipmentAttachments`, then `SetFilter("File Type", '<>%1', DocumentAttachment."File Type"::Image)`, then `exit(DocumentAttachment.Count())`.
   - `internal procedure CountImages(EquipmentNo: Code[20]): Integer`: the same, but with `SetRange("File Type", DocumentAttachment."File Type"::Image)`.
   - `internal procedure ShowAttachments(EquipmentNo: Code[20])`:
     - Exit if EquipmentNo = '' or `not Equipment.Get(EquipmentNo)`.
     - Otherwise `RecRef.GetTable(Equipment)`, `DocumentAttachmentDetails.OpenForRecRef(RecRef)`, `DocumentAttachmentDetails.RunModal()`.
     - Do not use SetLoadFields on Equipment, so the RecRef is complete.
   - `local procedure FilterEquipmentAttachments(var DocumentAttachment: Record "Document Attachment"; EquipmentNo: Code[20])`: `Reset()`, `SetRange("Table ID", Database::"EQM Equipment")`, `SetRange("No.", EquipmentNo)`.
   - Every procedure uses its own local record variable. Nothing is written, so there is no locking and no Commit.
   - Add XML doc comments in the style of `EQMMaintenanceMgt`.
   - Why: logic that can be tested, kept out of the page. Filtering on the PK prefix keeps the count cheap.

## Tests
New codeunit 50194 "EQM Equipment FactBox Tests":

**Summary rules**
- [SCENARIO 1] Summary shows the status and assigned employee of assigned equipment.
  - [GIVEN] Employee EMP with a first and last name. Equipment E marked Assigned to EMP.
  - [WHEN] The card of E is opened.
  - [THEN] `EquipmentSummary.Status` = Format(Assigned). `"Assigned Employee No."` = EMP. `EmployeeName` = Employee.FullName().
- [SCENARIO 2] (negative) Available equipment shows no employee.
  - [GIVEN] Equipment E with status Available and no employee.
  - [WHEN] The card is opened.
  - [THEN] Status = Format(Available). Assigned Employee No. and EmployeeName are blank.
- [SCENARIO 3] Warranty Status is Expiring Soon inside the 30-day window.
  - [GIVEN] E with "Warranty End Date" = Today() + Random(30) - 1, set directly with Modify(false).
  - [WHEN] The card is opened.
  - [THEN] `EquipmentSummary.WarrantyStatus` = Format(Expiring Soon).
- [SCENARIO 3b] Warranty Status is Active beyond the window.
  - [GIVEN] End date = Today() + 31 + Random(300).
  - [THEN] WarrantyStatus = Format(Active).
- [SCENARIO 3c] (negative) Warranty Status is Expired when the end date has passed.
  - [GIVEN] End date = Today() - Random(30).
  - [THEN] WarrantyStatus = Format(Expired).
- [SCENARIO 3d] (negative) Warranty Status is blank without an end date.
  - [GIVEN] E without a warranty end date.
  - [THEN] WarrantyStatus = Format("EQM Warranty Status"::" ").

**Statistics rules**
- [SCENARIO 4] Assignment Count counts active and closed entries of this equipment only.
  - [GIVEN] E with N = Random(5) closed entries and 1 active entry. Equipment E2 with Random(3) entries.
  - [WHEN] The card of E is opened.
  - [THEN] `EquipmentStatistics.NoOfAssignments` = N + 1.
- [SCENARIO 5] Maintenance Count and Total Maintenance Cost come from posted history.
  - [GIVEN] E with M = Random(4) history entries with random costs (Random(10000) / 100), sum S.
  - [THEN] NoOfPostedMaintenances = M and TotalMaintenanceCost = S.
- [SCENARIO 5b] (negative) Open maintenance and other equipment are not counted.
  - [GIVEN] E with one open "EQM Maintenance Record" and no history. E2 with one history entry.
  - [THEN] For E: NoOfPostedMaintenances = 0 and TotalMaintenanceCost = 0.
- [SCENARIO 6] (negative, empty) Equipment without history shows zeros.
  - [GIVEN] New saved E.
  - [THEN] All three Statistics values are 0.

**Attachment rules (codeunit 50137 called directly)**
- [SCENARIO 7] Documents and images are counted separately.
  - [GIVEN] For E: I = Random(3) rows with File Type Image, and D = Random(3) rows of non-image types (PDF, plus one with a blank File Type).
  - [WHEN] CountDocuments(E) and CountImages(E) are called.
  - [THEN] They return D and I.
- [SCENARIO 7b] (negative) Other equipment and other tables are not counted.
  - [GIVEN] Image and document rows for E2, and rows for Table ID = Database::Customer with "No." = E's number.
  - [THEN] CountDocuments(E) = 0 and CountImages(E) = 0.
- [SCENARIO 7c] (boundary) A blank equipment number returns 0.
  - [WHEN] CountDocuments('') and CountImages('') are called.
  - [THEN] Both return 0 and no error is raised.
- [SCENARIO 7d] A text file saved through the standard framework counts as a document.
  - [GIVEN] E, and a file 'fbfile1.txt' saved with `SaveAttachmentFromStream`, as in 50179.
  - [THEN] CountDocuments(E) = 1 and CountImages(E) = 0.

**UI wiring**
- [SCENARIO 8] The card shows the attachment counts.
  - [GIVEN] E with 2 image rows and 1 PDF row.
  - [WHEN] The card is opened.
  - [THEN] `AttachmentSummary.NoOfDocuments` = 1 and `NoOfImages` = 2.
- [SCENARIO 9] (negative) A new card shows empty FactBoxes without error.
  - [WHEN] `EquipmentCard.OpenNew()` is called.
  - [THEN] NoOfAssignments = 0, NoOfDocuments = 0, NoOfImages = 0, EmployeeName = '' and WarrantyStatus is blank. The three parts are Visible().

## Assumptions
- The new FactBoxes are added next to the existing parts, which are all kept visible. Removing or hiding them is not requested, and removing page controls becomes breaking after release.
- "Image Count" means attachments whose standard File Type is Image, and "Document Count" means all other attachments, so the two numbers add up to the total. The equipment Picture is a single MediaSet image already shown in the Picture FactBox. The FactBox is named "Attachments" in the issue.
- "Maintenance Count" means posted maintenances ("No. of Posted Maintenances"), because the Total Maintenance Cost next to it covers posted maintenance only. Open records stay visible in the existing Maintenance FactBox.
- The caption is 'Attachment Summary' rather than 'Attachments', because the standard attachment list part on the card is already captioned 'Attachments'.
- The page and object names are "EQM Equipment Stats. FactBox" and "EQM Attachment Count FactBox", because "EQM Equipment Statistics FactBox" is longer than 30 characters.
- No `Access = Internal` on the new pages, to match all 37 existing pages. The codeunit is Internal, as the skill requires.
- The tests use Locked Tok labels plus the built-in `Random()`, because the test app depends only on Library Assert. Adding a test-library dependency is an `app.json` change, which is on the stop list. This follows the pattern of 50179 and 50162.
- Return 0 when the user cannot read Document Attachment, rather than raising an error in the FactBox. Reader has R on it, so this only matters for custom roles.

## DECISIONS
- FR-037 FactBoxes | Chose three new CardPart pages over extending "EQM Equipment FactBox" and "EQM Maintenance FactBox", because the issue defines three named FactBoxes with their own content, and the existing parts are reused on 4 other pages | Reversible: yes
- FR-037 FactBoxes | Chose to keep the existing Assignment Details and Maintenance FactBoxes visible on the card over hiding them (Visible = false). The FactBox pane grows to 9 parts, against the Learn guidance of one to three; hiding them is a non-breaking follow-up if the user wants it | Reversible: yes
- FR-037 FactBoxes | Chose Image = Document Attachment "File Type" Image, and Document = every other attachment, over counting the equipment Picture or classifying by "EQM Attachment Category" (which has no image value) | Reversible: yes
- FR-037 FactBoxes | Chose Maintenance Count = posted maintenances (FlowField 15) over all maintenance records including open ones, so count and total cost describe the same set | Reversible: yes
- FR-037 FactBoxes | Chose a new internal codeunit "EQM Equipment Attachment Mgt." over FlowFields on table 50100 ("No. of Documents"/"No. of Images"), to avoid widening the published table schema and API surface | Reversible: yes

## Risks
- **Field "File Type" and enum member `Image` on Document Attachment are not verified.** al_symbolsearch was unavailable. The FR-024 report only confirms that enum 1174 "Document Attachment File Type" exists. The compile in step 7 is the check; if it fails, the developer stops and reports.
