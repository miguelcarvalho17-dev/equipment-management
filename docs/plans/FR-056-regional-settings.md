# FR-056 Regional Settings — Plan

> Request (verbatim): FR-056 Regional Settings
> Status: **approved**

## Request

Make the app show dates, numbers and amounts in the user's Business Central regional format (My Settings > Region). An audit of `app/src` found one place where users see non-regional values: the Maintenance Log Entries page (50121). It shows the stored Old Value / New Value in XML format, for example `2026-11-19`, `1234.5`, and `1` instead of "Corrective". The fix adds display-only regional columns there. Everything else already follows the regional settings, and the audit result goes into the feature doc.

Target: AppSource

## Audit result

| Area | Finding | Action |
|---|---|---|
| Amount fields (tables 50100, 50104, 50105, 50106, 50113) | Every money Decimal has `AutoFormatType = 1` (LCY). The client formats them by Region | None |
| Percent page variables (50120 list, maintenance FactBox) | `DecimalPlaces = 0 : 1`, typed Decimal | None |
| Dates and DateTimes on pages and FactBoxes | Typed Date/DateTime fields and variables. None are pre-formatted to text | None |
| Messages, errors, confirms, notifications (`StrSubstNo`, `Error`, `Message`) | Dates, integers and decimals are passed as typed values, so AL formats them by the user's region. Enums use `Format(enum)` = translated caption | None |
| Date formulas (`<%1M>`, `<1D>`, `<-CM>`, `<CM>`, `<-CY>`) | Angle-bracket formulas do not depend on language or region | None |
| `SetFilter` with dates | Uses `%1` placeholders with typed values, not text | None |
| Reports 50100–50102 | Compiler-generated Excel layouts take native Date/Decimal cells. The request page has Language/Format Region | None |
| Charts (50116–50119) | Pass Decimal values to the BusinessChart control | None |
| Telemetry EQM0001–EQM0009, business events, API pages | Machine-readable on purpose: `Format(x, 0, 9)`, enum Names() (FR-050 decision) | None. Must stay invariant |
| Maintenance log (table 50108, page 50121, codeunit 50116) | Stores values with `Format(value, 0, 9)` (NFR-005 Q4, user-approved). The page shows the raw XML text to users | Fix in this plan: display-only conversion. Storage unchanged |
| Hard-coded currency symbols, date patterns, number masks | None found in `app/src` | None |

## Definition of done

- [ ] Page 50121 "EQM Maintenance Log Entries" shows two new columns, captions "Old Value" and "New Value", for Changed entries in the user's regional format:
  - Maintenance Date as `Format(Date)`.
  - Cost as `Format(Decimal)`, with regional decimal and thousands separators.
  - Maintenance Type as the translated enum caption.
  - Vendor No., Description and Performed By exactly as stored.
- [ ] The existing raw controls "Old Value" / "New Value" stay on the page with `Visible = false` and page captions "Old Value (XML Format)" / "New Value (XML Format)". Users can still show them through personalization.
- [ ] Table 50108 fields 6 and 7 and everything written by codeunit 50116 are unchanged: storage stays `Format(value, 0, 9)`.
- [ ] A stored value that cannot be converted is shown as stored and never raises an error (unparsable text, enum ordinal not installed, blank value).
- [ ] Registered and Posted entries (Field No. 0, blank values) show blank regional columns.
- [ ] No database access is added per row. The conversion is pure in-memory.
- [ ] No new objects, IDs, permission set entries or app.json changes.
- [ ] XLIFF `app/Translations/Equipment Management.g.xlf` is regenerated by the build and contains the new captions and ToolTips.
- [ ] app/ compiles with CodeCop, UICop and AppSourceCop with 0 warnings. test/ compiles. The AppSourceCop breaking-change check against the baseline passes.
- [ ] New tests in 50164 compile. CI result is read after push.
- [ ] `repo_checks.py` passes locally, including coverage check 5.

## Out of scope

- Changing the stored log format (NFR-005 Q4 stands). No upgrade or data conversion.
- Currency-specific decimal places (GL Setup "Amount Decimal Places" through the "Auto Format" codeunit). Phase 2.
- Adding `AutoFormatExpression` to the existing amount fields (CodeCop AA0472/AA0474 Info).
- Word/RDLC layouts and a report `FormatRegion` (no such layouts exist).
- Translations into other languages (FR-055).
- Telemetry, business events and API (they must stay invariant).

## Events and standard symbols

None. Only AL built-ins are used: `Evaluate(var Variable; String: Text; Number: Integer): Boolean`, `Format(Value: Any): Text`, `Enum.Ordinals(): List of [Integer]`, `Enum::"EQM Maintenance Type".FromInteger(Integer)`. `al_symbolsearch` had no project loaded, so no standard symbol is planned.

## Steps

1. `EQMMaintenanceLogMgt.Codeunit.al`: after `LogPosted`, add (with XML doc comment) `internal procedure FormatLogValueForDisplay(FieldNo: Integer; StoredValue: Text): Text`.
   Locals: `MaintenanceRecord: Record "EQM Maintenance Record"` (only for `FieldNo(...)`), `MaintenanceType: Enum "EQM Maintenance Type"`, `DateValue: Date`, `DecimalValue: Decimal`, `Ordinal: Integer`.
   Logic: `if StoredValue = '' then exit('');` then `case FieldNo of`
   - `"Maintenance Date"`: `if Evaluate(DateValue, StoredValue, 9) then exit(Format(DateValue));`
   - `Cost`: `if Evaluate(DecimalValue, StoredValue, 9) then exit(Format(DecimalValue));`
   - `"Maintenance Type"`: `if Evaluate(Ordinal, StoredValue, 9) then if MaintenanceType.Ordinals().Contains(Ordinal) then begin MaintenanceType := Enum::"EQM Maintenance Type".FromInteger(Ordinal); exit(Format(MaintenanceType)); end;`

   Then `exit(StoredValue);` as the fallback. No `Error`.
2. `EQMMaintenanceLogEntry.Table.al`: after `AllowInsertFromLog`, add `internal procedure GetLocalOldValue(): Text` and `internal procedure GetLocalNewValue(): Text`, each delegating to `MaintenanceLogMgt.FormatLogValueForDisplay(Rec."Field No.", Rec."Old Value" / Rec."New Value")`. Doc comments say storage is unchanged. Fields 6/7 untouched.
3. `EQMMaintenanceLogEntries.Page.al`: in `repeater(Entries)`, after `field("Field Caption"; ...)`, add `field(OldValueLocal; Rec.GetLocalOldValue())` (Caption `Old Value`, ToolTip `Specifies the value of the field before the change, shown in the format of your region.`) and `field(NewValueLocal; Rec.GetLocalNewValue())` (Caption `New Value`, ToolTip `Specifies the value of the field after the change, shown in the format of your region.`). On the existing `Old Value` / `New Value` controls add `Visible = false;` and Caption `Old Value (XML Format)` / `New Value (XML Format)`. Optionally extend `AboutText`.
4. Build `app/`: `al_compile` + `al_getdiagnostics`, expect 0 warnings. Regenerated `.g.xlf` gets the new trans-units.
5. `EQMMaintenanceTests.Codeunit.al`: append tests R1–R5 and N1–N4 (below), add helper `FindChangedLogEntry`, global `MaintenanceLogMgt`, extend summary comment with FR-056. Each test `[TransactionModel(TransactionModel::AutoRollback)]`.
6. Compile `test/` (copy fresh app symbol into `test/.alpackages`, gitignored).
7. Run `python3 .github/scripts/repo_checks.py --base origin/main --branch feature/FR-056-regional-settings`; add a coverage-register entry only if check 5 asks for it.
8. Docs step: `docs/features/FR-056-regional-settings.md` (with audit table), `docs/help/FR-056-regional-settings.md`, `CHANGELOG.md` heading `## FR-056`.

## Tests

All in 50164 "EQM Maintenance Tests". Expected values use `Format(...)` in the same session, so they hold under any Region.

- R1 Changed cost: `GetLocalOldValue() = Format(C1)`, `GetLocalNewValue() = Format(C2)`, stored Old Value still evaluates (format 9) to C1.
- R2 Changed maintenance date: local values equal `Format(D1)` / `Format(D2)`.
- R3 Changed maintenance type Preventive → Inspection: local values equal the enum captions, and differ from the stored ordinal.
- R4 Description change: local values equal the stored values.
- R5 TestPage 50121: `OldValueLocal` = `Format(C1)`, `NewValueLocal` = `Format(C2)`.
- N1 Unparsable stored cost is returned as stored, no error.
- N2 Unparsable stored date is returned as stored.
- N3 Uninstalled enum ordinal is returned as stored, no error.
- N4 Registered entry has blank local values.
- Existing `EQMProcessIntegrationTests` (50158) lines 329–331 read the stored XML value, unchanged, must stay green.

## Assumptions

- Display-time conversion is compatible with NFR-005 Q4, which fixes storage only.
- Plain `Format(Decimal)` is enough for the logged Cost (always LCY; other amount fields already use `AutoFormatType = 1`).
- "Respect regional settings" means output shown to users; telemetry, business events and API stay invariant.
- `case` labels using `MaintenanceRecord.FieldNo(...)` compile; fallback is an `if ... else if` chain.

## Risks

- No standard symbol verified (AL MCP had no project loaded); the plan avoids base symbols. Reviewer confirms none crept in.
- `Format(0D, 0, 9)` for a cleared date: either shows blank or the raw text. Both acceptable.
- `FromInteger` on unknown ordinal is guarded by `Ordinals().Contains`; reviewer checks the guard comes first.
- Two "Old Value" columns on the page (one hidden); reviewer checks the hidden ones got the "(XML Format)" caption.
- AppSourceCop baseline: only additions, Visible/Caption changes and new internal procedures; reviewer runs the comparison.
- Phase 2: LCY decimal places via "Auto Format" codeunit; `AutoFormatExpression` on amount fields.
- No separate AppSource validation runs.

## Decisions

- Display-time conversion over changing stored format (NFR-005 Q4; migration would be stop-list). Reversible.
- New controls `OldValueLocal`/`NewValueLocal` plus hiding/recaptioning raw ones, so no published control changes meaning. Not reversible.
- Plain `Format(Decimal)` for Cost; LCY precision is phase 2. Reversible.
- Unconvertible values shown as stored (no error, no blank). Reversible.
- New procedures are `internal`. Reversible.
- Tests added to existing 50164 (free test IDs reserved; widening test/app.json is stop-list). Reversible.
- Nothing else changed after the audit. Reversible.
