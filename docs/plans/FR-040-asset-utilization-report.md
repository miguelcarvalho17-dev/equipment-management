> Request (verbatim): "FR-040 Asset Utilization Report. The system shall provide utilization statistics. Metrics: Total Equipment, Assigned Equipment, Available Equipment, Utilization %. Formula: Assigned / Total Equipment * 100" (GitHub issue #78)

## Request
Add an Asset Utilization report. It shows Total, Assigned, Available and In Maintenance equipment and Utilization % (= Assigned / Total * 100), for the equipment that matches the user's request-page filters. Source: GitHub issue #78 (FR-040). Follows the FR-039 report pattern (Excel layout, Tell Me, Equipment List Report group, Role Center Reporting area, Reader permission, SaveAs-based tests).
Target: AppSource

## Steps
1. **`app/src/Dashboard/EQMDashboardMgt.Codeunit.al`**: add two internal procedures at the end of the codeunit, each with `/// <summary>` and `<param>`/`<returns>` doc comments in the house style.
   ```al
   /// <summary>
   /// Counts the equipment for the asset utilization within the filters of the given record. Lost and disposed
   /// equipment is never counted. Total counts every other status, including statuses added by extensions.
   /// The filters on the given record are not changed.
   /// </summary>
   internal procedure CalcAssetUtilization(var Equipment: Record "EQM Equipment"; var TotalEquipment: Integer; var AssignedEquipment: Integer; var AvailableEquipment: Integer; var InMaintenanceEquipment: Integer)
   var
       FilteredEquipment: Record "EQM Equipment";
   begin
       FilteredEquipment.CopyFilters(Equipment);
       // Filter group 10 is outside the groups the platform uses (0-7), so a user filter on Status in group 0 still applies
       FilteredEquipment.FilterGroup(10);
       FilteredEquipment.SetFilter(Status, '<>%1&<>%2', FilteredEquipment.Status::Lost, FilteredEquipment.Status::Disposed);
       TotalEquipment := FilteredEquipment.Count();
       FilteredEquipment.SetRange(Status, FilteredEquipment.Status::Assigned);
       AssignedEquipment := FilteredEquipment.Count();
       FilteredEquipment.SetRange(Status, FilteredEquipment.Status::Available);
       AvailableEquipment := FilteredEquipment.Count();
       FilteredEquipment.SetRange(Status, FilteredEquipment.Status::"In Maintenance");
       InMaintenanceEquipment := FilteredEquipment.Count();
   end;

   /// <summary>
   /// Returns the utilization percentage: assigned equipment divided by total equipment, times 100, rounded to two decimals.
   /// Zero when there is no equipment.
   /// </summary>
   internal procedure CalcUtilizationPct(AssignedEquipment: Integer; TotalEquipment: Integer): Decimal
   begin
       if TotalEquipment <= 0 then
           exit(0);
       exit(Round(AssignedEquipment * 100 / TotalEquipment, 0.01));
   end;
   ```
   Why here: the codeunit already holds the dashboard data helpers and Reader already has Execute, so no new object or permission line. A fresh local record is used, so the caller's record and filters are never touched. `Count()` runs one SQL COUNT per figure: no loop, no lock, no Commit.

## Tests
New codeunit 50196 "EQM Asset Utilization Tests". C1 and C2 are fresh test categories. A, S, M, L and D are Random(5) quantities.

**Counting (CalcAssetUtilization)**
- [SCENARIO 1] Counts per status within the filter.
  - [GIVEN] In C1: A Available, S Assigned and M "In Maintenance" equipment.
  - [WHEN] CalcAssetUtilization runs on a record filtered on Category Code = C1.
  - [THEN] Total = A+S+M, Assigned = S, Available = A, In Maintenance = M.
- [SCENARIO 2] (negative) Lost and Disposed are not counted.
  - [GIVEN] In C1: 1 Available, 1 Assigned, L Lost and D Disposed.
  - [WHEN] Same as SCENARIO 1.
  - [THEN] Total = 2, Assigned = 1, Available = 1, In Maintenance = 0.
- [SCENARIO 3] (negative) Equipment outside the filter is not counted.
  - [GIVEN] 1 Assigned in C1, S Assigned in C2.
  - [WHEN] Filter on C1.
  - [THEN] Total = 1 and Assigned = 1.
- [SCENARIO 4] A user Status filter combines with the rule.
  - [GIVEN] In C1: A Available and S Assigned.
  - [WHEN] Filter C1 and Status = Assigned.
  - [THEN] Total = S, Assigned = S, Available = 0, and CalcUtilizationPct gives 100.
- [SCENARIO 5] (negative) A user filter on a final status still counts nothing.
  - [GIVEN] In C1: D Disposed.
  - [WHEN] Filter C1 and Status = Disposed.
  - [THEN] Total = 0 and Assigned = 0.
- [SCENARIO 6] The caller's filters are kept.
  - [GIVEN] A record filtered on C1; store `GetFilters()`.
  - [WHEN] CalcAssetUtilization runs.
  - [THEN] `GetFilters()` is unchanged, and `FilterGroup()` on the caller's record is still 0.

**Percentage (CalcUtilizationPct)**
- [SCENARIO 7] Utilization = Assigned / Total * 100, rounded to 0.01.
  - [GIVEN] In C1: A Available and S Assigned (Random(9) each, so non-round results occur).
  - [WHEN] Calc runs on C1, then CalcUtilizationPct.
  - [THEN] Result = Round(S * 100 / (A + S), 0.01).
- [SCENARIO 8] (failure path) No equipment gives 0 % without a division-by-zero error.
  - [GIVEN] Empty category C1.
  - [WHEN] Calc runs on C1, then CalcUtilizationPct.
  - [THEN] Total = 0 and the percentage = 0.

**Report (SaveAs XML)**
- [SCENARIO 9] The report runs and emits the summary columns.

  - [WHEN] Report.SaveAs XML with filter C1.
  - [THEN] The output is not empty and contains UtilizationColumnTok and TotalColumnTok.
- [SCENARIO 10] (failure path) The report runs when no equipment matches.

## Assumptions
- **Total Equipment excludes Lost and Disposed** because they can never be assigned (final statuses). Including them would push utilization down permanently as equipment is written off. Consequence: the report's Total differs from the dashboard "Total Equipment" tile (all statuses). The help explains this.
- An extra **In Maintenance** column is acceptable because without it Total ≠ Assigned + Available.
- **Two-decimal rounding** (Round(..., 0.01)), standard in BC reports.
- **Category Code and Location Code** as default filters; every other field can still be added with "+ Filter".
- "Statistics" means one summary row for the filtered set; a per-category breakdown is phase 2.
- The generated Excel layout (a Data sheet with 5 columns) is an acceptable first delivery, as in FR-039.
- The XML from `Report.SaveAs(..., ReportFormat::Xml, ...)` contains the column names as text. If not in the sandbox, scenarios 9 and 10 fall back to asserting non-empty output; this is reported, not silently changed.
- No mismatch found between `CLAUDE.md` and `app/app.json`.

- **Performance.** Four COUNT queries with the request filters, no locks, no loop. No new key.
- **Multi-company and concurrency.** Read-only, current company only, no Commit.
